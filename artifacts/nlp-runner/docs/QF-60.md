# Story QF-60 — NL query entry point

`qf run "<query>"` auto-decides: embed -> similarity match -> replay, disambiguate, or record. Slot values in the new query re-fill the matched test's slots (heuristic first, LLM fallback only when needed). Recorded-run metrics (`llm_calls`) stay `0` on the pure-replay path.

Implementation: `src/cli.ts` (dispatch), `src/planner/nl-query.ts` (pure decision/refill/prompts), `src/embeddings/matcher.ts` (`matchAll`), `src/replay/engine.ts` (`llmCalls` offset).

Prereq: `fixture/server.ts` on port 3123: `npx tsx fixture/server.ts` -> `http://127.0.0.1:3123`.

## Task QF-61 — Auto record-or-replay decision in `run "<query>"`
1. Empty DB. `qf run "register jane@y.com on signup"` (fixture up). No exact query match and no similarity match -> CLI prompts "No starting URL in the query. What page should I start on?". Enter `http://127.0.0.1:3123/signup`; the agent records (dry-run gate passes).
2. Run the **same** query again -> exact query match -> `mode: replay`, `llm_calls: 0`, no recorder browser launch.
3. New query with no URL, e.g. `qf run "what is 2+2"` -> below the 0.85 threshold -> record path; prompts for a starting URL (Enter to cancel).
4. `qf run "do the thing" --entry-url http://127.0.0.1:3123/signup` skips the prompt and records immediately.

## Task QF-62 — Slot re-fill on replay (heuristic + LLM fallback)
Prereq: cached test with `query` = `register bob@x.com on signup`, `email` slot (default `bob@x.com`).
1. `qf run "register jane@y.com on signup"` -> similarity replay. Heuristic maps the single email token to the `email` slot; the fill step types `jane@y.com`. Log shows `llm_calls: 0`.
2. Name slot whose value isn't regex-detectable: cached query `register Ada on signup` (name=`Ada`), new query `register Jane on signup`. `Jane` is a single Title-case token (name regex needs 2+ words) -> LLM fallback fills `name=Jane`; log shows `llm_calls: 1`.
3. Re-run #1 identically -> exact match, no re-fill, `llm_calls: 0`.
4. `qf run "register jane@y.com on signup" --variables '{"email":"x@y.com"}'` -> `--variables` short-circuits re-fill; `llm_calls: 0`.

## Task QF-63 — Ambiguity prompt
1. Seed two similar cached tests; run `qf run "register on signup"` -> both within the ambiguity margin of the top score. CLI prints numbered candidates; type `1`/`2` to replay the chosen test.
2. `qf run "register on signup" --test 5` -> bypasses the prompt, replays test #5 directly.
3. Press Enter at the prompt -> `run: cancelled`, exit 1, no run.

## Acceptance-criteria verification
| Criterion | Verified by |
| --- | --- |
| Auto: match -> replay; no match -> record; ambiguous -> prompt | `decideRun` in `nl-query.test.ts` (record/replay/disambiguate branches); `runCommand` wires each branch. |
| Slot re-fill: heuristic first, LLM fallback | `refillVariables` tests: email swap heuristic (`usedLlm:false`); ambiguous tokens / undetectable names -> LLM (`usedLlm:true`). |
| Query with variables runs cached test, `llm_calls: 0` on pure-replay | `buildReplayVariables` uses `--variables` directly; `ReplayRunner.runTest` persists `options.llmCalls` into the run (`engine.test.ts`); heuristic path is `0`. |
| `--test <id>` bypasses the prompt | `parseRunArgs` parses `--test`; `runCommand` fetches by id before matching (`cli.test.ts`). |
| Record with no URL context asks for a starting URL | `runCommand` record branch calls `resolveStartUrl`; null -> prompts. |
